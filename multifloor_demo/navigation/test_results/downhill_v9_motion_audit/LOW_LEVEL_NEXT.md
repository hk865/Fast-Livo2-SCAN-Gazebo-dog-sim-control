# Bounded recommendation for the next low-level controller

The current low-speed yaw/translation tracking remains inadequate in v8 and v9 despite correct goal identity, command limits and stop/replan handshakes. Further NAV gain increases are not supported by these observations. A more appropriate successor to investigate is a **joint-state/IMU feedback locomotion backend**, keeping NAV/SCAN/SLAM regions and independent protection above it. If Root selects the existing RL branch, the most direct saved interface prototype is the identity-verified STAGE3-FLAT003 ONNX actor with its external data file. It is not a qualified Gazebo controller: its existing rapid command-transition gate failed, its declared deployment actuator limits differ from the evaluated plant, and neither this Demo's low-speed commands nor its downhill stop/restart contract has a policy PASS.

The target architecture is the training-consistent multirate contract: a stateless 45→12 actor every 20 ms of physical time, followed by measured-joint PD at the evaluated 5 ms servo/physics cadence (decimation 4). Restore the exact gyro/gravity/body command/q−default/qdot/previous-raw-action inputs, scale and joint-name mapping. Apply `q_target = default_q + 0.25 * action` with the original evaluated actuator model and finite/limit checks. GT must stay evaluation-only. This is a design recommendation for an isolated backend qualification, not authorization to load or run the model.

The current JTC profile cannot be silently reused. P220.982919 versus training P25 changes nominal stiffness by 8.84×; D1 versus .5 doubles the velocity term, and the current I=.2 is not part of the stated RL PD law. The JTC 4 ms/250 Hz update and position-only 16,666,666 ns interpolation horizon change target timing/reference velocity. The current CHAMP stop nominal differs from RL default joint posture. Carrying these settings across changes the controller and the policy's observation/action transition distribution; matching only the twelve joint names is insufficient.

Conversely, selecting P25/D.5 alone does not reproduce the evaluated RL plant. STAGE3 uses a DCMotor model with 23.5 Nm on all joints and velocity-related behavior; the current Demo has hip/upper 23.7 Nm and lower 35.55 Nm, different velocity limits, inertial layout, passive damping and contact engine. Gazebo's 1 ms physics step and the 4 ms CM period require an explicit timing/actuator equivalence decision rather than assuming 50 Hz policy output makes the differences disappear. The existing action stream is not limited to ±1, and the real ONNX external data and joint order must be retained.

The smaller interface alternative remains a measured-joint classical PD backend with explicit physical-time torque hold and total command limiting, rather than using trajectory interpolation/effort carry as an implicit gain multiplier. No gains for that alternative are chosen here. Both alternatives need a trusted profile that distinguishes position target, desired effort/feedforward, commanded effort and actual physical force. The current rigid-body and native JTC tests establish mathematical/interface boundaries only, not a stable contact controller.

Before any RL adoption, qualify one command owner, fresh measured inputs, exact actor identity and serialization provenance, zero/stop acknowledgment and restart semantics, physical-time scheduling, finite bounded joint outputs and the original actual motion/tilt/region contracts. The existing safe stop handshake must remain independent of the policy. Current `.12/.08` mixed commands, low-speed ALIGN compensation, slope/downhill and obstacle waits are outside the saved policy's demonstrated coverage; no existing report closes those gaps.
