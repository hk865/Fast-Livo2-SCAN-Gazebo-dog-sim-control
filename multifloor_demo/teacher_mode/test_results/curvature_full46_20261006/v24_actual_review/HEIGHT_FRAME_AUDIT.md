# 27bd 第12区高度与坐标系核对

**初始 yaw-only 注册所忽略的 roll/pitch，不能单独解释此次 −172.06 mm 高度误差。更晚的定位/重力变化仍未证实；不是信号中断原因的证明。**

末个导航位置为 camera_init `[16.074055, 6.795549, 1.031558]`，原第12区中心 `[16.077614, 6.840156, 1.203617]`，误差 `[-3.56, -44.61, -172.06] mm`。水平距离约44.75 mm，但原高度半范围100 mm未满足。原到达判据保持不变。

路线确实只应用一次冻结 yaw 和初始实测位置；没有完整 roll/pitch 旋转。注册先用完整 IMU/SLAM 姿态对检查重力轴，再提取 yaw，代码明确假设两者重力对齐。26个实际初始配对的最大重力残差仅0.001891 rad（0.108°），小于原3°门。离线对原 `[16,7,1.2]` 偏移应用每个完整初始相对旋转、保持同一初始原点，第12目标z比当前 yaw 目标增加22.12–29.14 mm（均值24.94 mm）；这会使当前负误差更大，无法消除172 mm误差。此计算没有修改实际路线。

冻结配置启用 IMU 静止初始化和一次重力对齐：初始化后同时旋转状态位置、姿态、速度和重力；后续重力与偏置估计也开启。初始化证明中的640个IMU样本，经其记录的世界姿态旋转后，平均加速度约 `[0.001285, 0.000983, 9.811619] m/s²`，没有显示大角度重力轴错误。但这份证明明确没有读取滤波器内部偏置，不能用它代替实际内部初始化/后续重力历史。

固定外参中 IMU 位于 body 原点、旋转为单位阵；LiDAR–IMU 平移 `[0.2,0,0.1177]` 与实际配置一致。`camera_init`在此是经过重力初始化的SLAM参考系，不能仅凭名称当成相机光学坐标系。

还需更正 native 字段术语：冻结 `teacher_actuator.cpp` 从 `base_link.WorldPose().Pos()` 填入 request[1:4]，`policy/worker.py` 原样写 `state.position`；仅线速度使用COM偏移。因此末帧 `[16.019610,6.977550,1.501709]` 是 native base-link world 位置，不能再减一次COM位置偏移，也不能直接与 camera_init z 相减。末 native 物理时间267.185 s与末 cascade SLAM反馈266.215 s相差约0.970 s。

严格比较仍缺：初始同时间的 native base-link 完整位置/四元数与SLAM位姿（当前初始化安全证明只保留rpy/clearance等，未保留位置或四元数）；晚期同时间的 SLAM/IMU/native 姿态位置；以及第11→12区间重力、偏置与地图残差历史。应先用这些建立固定SE3和同时间比较，再区分坐标估计变化、地图误差或实体运动，不能先定性为运动漂移。
