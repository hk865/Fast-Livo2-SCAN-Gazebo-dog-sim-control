# V19 staged input pipeline (implemented; limited core validation only)

`FASTLIVO_PIPELINE_MODE=serial|rx_decode|staged` controls scheduling only. All modes preserve V18 LIO-4/VIO-1, the complete estimator prior and floating-point expressions. The original callbacks run on one estimator owner. State, bias, sync buffers, map, diagnostics context and publications stay on that owner; IMU→LIO→VIO estimation remains sequential across frames.

A single ROS SingleThreadedExecutor receives a message reference, assigns one global sequence/source stamp/original monotonic receipt, and atomically admits a slot. In `serial`, decode and commit occur on the owner callback. In `rx_decode`, the receiver also decodes before marking ready. In `staged`, a dedicated cloud thread exclusively owns Preprocess scratch and a separate image thread produces owned cv::Mat data. IMU and timer slots become ready immediately. Ready results are committed by increasing global sequence, so a later IMU/timer cannot overtake a still-decoding cloud/image. A snapshot of admitted slots limits each owner draining pass, preventing continuous ingress from starving estimation.

The admission budget is **512 packets / 64 MiB total**, including raw, decoder-inflight, ready and owner-inflight slots until commit acknowledgement. Each slot reserves raw capacity plus a conservative decoded/scratch upper bound before decoding; size arithmetic is checked. Cloud scratch is released after each decode so unaccounted high-water storage cannot persist. Overflow is a visible terminal failure; there is no drop, replacement or thinning. Middleware queues and existing committed SLAM buffers are outside this admission budget and are reported as such, not claimed as globally bounded memory.

`SIGUSR1` requests a normal stop while the ROS context remains valid. The owner cancels timer and RX dispatch, joins RX (allowing its current callback to finish admission), seals the queue admission barrier only after RX is quiescent, then finishes/joins both decoders, commits every accepted slot in original order, and requires `pending=0`, `accepted=delivered=committed`, no cancellation, no post-barrier rejection and no failure before writing `normal_completed=true`. Only then does main call ROS shutdown. `SIGINT` remains emergency shutdown: invalid context forbids further owner publications, joins workers, records every uncommitted accepted identity and reason, and produces a failed summary. Overflow, decode/commit exception and trace failure are also explicit failures. An exception from decoding is held in the packet and rethrown at the original callback after its original header rejection gates, preserving old duplicate/backward/too-close-frame semantics.

Trace clocks are monotonic wall and calling-thread CPU nanoseconds, with receive/decode/owner TIDs. They describe receive/admission, raw enqueue, decoder pop/begin/end, ready enqueue, owner pop/commit end, and lifecycle boundaries. Wall minus CPU is not labelled communication. Source header and receipt are never refreshed. Body hashes belong to test corpus identity, not a new hot-path per-byte hash. `FASTLIVO_IMAGE_COPY_OPT=0|1` is a separate opt-in copy-only change: default 0 preserves the original image message deep copy and post-conversion clone; 1 uses an immutable retained message and the already-owned conversion result.

The trace/summary schema and API are frozen before performance measurement. Production exact ordering is callback admission order, not rosbag record order. New finite arithmetic, malformed/header rejection, ordering/capacity, busy normal drain, exception/context stop and sanitizer checks are required. This design is implemented in the private V19 source. CORE_PREFLIGHT.json records successful limited arithmetic, packet, queue and lifecycle validation. It does not authorize runtime or claim actual Gazebo motion, mission46 or whole-pipeline speedup.
