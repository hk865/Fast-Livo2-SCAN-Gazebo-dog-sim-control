# 移植、构建与运行

## 一套源码与一个总入口

`start.py → bringup.main`读取`src/bringup/config/navigation.json`列出的模块配置，准备本次run、统一ROS域/Gazebo partition/IPC地址，取得互斥锁后启动唯一总launch。总launch包含定位、规划、控制、仿真四个子入口。仿真模块先让Actor加载Student并真实bind/listen，再放行Gazebo；SCAN子进程只归监督器拥有。

源码或模型的历史hash、旧run合同、旧PASS文件不参与启动。构建时的下载commit/hash和发行清单只用于来源与完整性；每帧消息内容、坐标代次与因果ACK校验仍是安全协议。

## Docker构建

默认`docker build --build-arg BUILD_JOBS=2 -t go2-navigation:local .`。基础环境为Ubuntu24.04/ROS Jazzy，Gazebo Harmonic，CPU PyTorch2.7.1；官方来源见Dockerfile。SDK2固定官方v1.3.1提交（提供本驱动实际引用的Mid360s枚举）；Fast DDS2.14.6及Asio使用`third_party/fastdds/SOURCES.json`中的官方archives和SHA256。

部分网络环境下官方Ubuntu/ROS源连接不稳定，可显式选择仍受官方apt签名校验的镜像，例如：

```bash
docker build --network=host \
  --build-arg UBUNTU_APT_MIRROR=https://mirrors.ustc.edu.cn/ubuntu \
  --build-arg ROS_APT_MIRROR=https://mirrors.ustc.edu.cn/ros2/ubuntu \
  --build-arg BUILD_JOBS=2 -t go2-navigation:local .
```

`--network=host`仅用于相应主机上的构建下载问题，不要求更改docker组、系统安全设置或关闭TLS/签名验证。日常仿真可在独立容器网络中运行。

构建脚本依次下载校验源、编译patched FastDDS及SHM组件测试、Livox SDK2、12个ROS包、Gazebo actuator、writer QoS helper。所有产物写入当前树`build/`和`install/`，不读取原机器`.local`。Fast DDS上游的嵌套Docker网络测试单独关闭配置，SHM心跳测试保留；不挂载Docker socket。

## 原生Linux构建

在与Dockerfile相同的Ubuntu24.04/Jazzy/Harmonic开发依赖、CPU PyTorch环境下：

```bash
source /opt/ros/jazzy/setup.bash
python3 -B build_support/build.py --jobs 2
export NAVIGATION_ACTOR_PYTHON=/你的CPU-PyTorch环境/bin/python3
python3 -B start.py --check
python3 -B start.py --resource-check
```

Actor解释器也可在总配置显式指定；auto使用`NAVIGATION_ACTOR_PYTHON`或当前Python，不再寻找Isaac Sim安装。ROS节点使用系统Python，Actor使用独立CPU PyTorch解释器。脚本会保护Fast DDS fresh构建目录；中途失败先检查日志，保留失败目录后用新目录或明确重新构建，不混旧CMake cache。

## 运行与输出

`--check`不需要启动ROS、加载模型或已有库就能列出文件缺项；`--prepare-only`生成world、相机/FAST-LIVO/SCAN参数、几何参考和本次context。完整运行输出在`runs/<UTC>_<label>_<随机标识>/`。

- `launch.log`：总launch与节点输出。
- `navigation_status.json`、`navigation_command.json`：活状态和当前命令。
- `closed_loop_executor_ack.json`：有界实际执行ACK，不是历史准入文件。
- `component_exit.jsonl`、`exit.json`：组件和入口的退出状态。

Ctrl-C由总入口先转交唯一launch进程，再由launch通知各组件；只有超时才升级到自己创建的进程组；不使用pkill全机扫描。`--duration`只设墙钟上限。不要把正常截断或所有进程消失当作导航成功，也不要让观察器通过掩盖组件异常退出。

## 验收分层

先跑`python3 -m unittest discover -s tests -v`，再做真实Student socket/next-request ACK组件检查，最后用干净构建产物运行`tools/validation/run_navigation_check.py --output <新目录>`。后者独立注入原moving_obstacle，要求实际stop/clear/recovery、固定T0后51格严格不同源戳的因果10Hz停车样本和窗口内零hold状态；阈值保持原值。

容器内完整验收可显式覆盖镜像入口，使用与普通运行相同的资源及runs挂载：

```bash
docker run --rm --cpus=6 --memory=12g --shm-size=2g \
  -e LIBGL_ALWAYS_SOFTWARE=1 -e EGL_PLATFORM=surfaceless \
  --mount type=bind,src="$(pwd)/runs",dst=/workspace/navigation/runs \
  --entrypoint /usr/bin/python3 go2-navigation:local \
  tools/validation/run_navigation_check.py --output runs/validation_new --wall-timeout 1800
```

普通运行在无GPU容器也使用这两个Mesa环境变量。输出目录必须尚不存在；CPU墙钟超时不修改仿真任务、停车或安全阈值。完整结果、动态结果、停车结果与退出结果分别记录。更新状态见[验证状态](验证状态.md)。
